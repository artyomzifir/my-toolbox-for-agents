# Переносимая библиотека процедур для исследовательского агента

Снимок открытых исходников от 3 ноября 2026 года. Библиотека входит в Goose Research Kit. Версии и лицензии исходников записаны в каталоге и `sources.lock.json`.

В снимке 194 исходных skill из семи каталогов, 22 файла команд и агентных процедур, 20 конфигураций и манифестов плагинов и пять публичных файлов промптов Codex.

## Назначение

Библиотека позволяет проверить гипотезу, что агенту не хватает процедур работы, навыков и инструкций. Здесь есть материалы для научного поиска, обзоров литературы, критики доказательств, гипотез, экспериментов, статистики, ML-инженерии, написания статей, кода и проверки результатов.

Готовность к переносу различается. Доступность файла и прохождение проверки его формата не доказывают качество на задачах пользователя. Модельные прогоны, настройка OAuth/MCP и запуск вспомогательных API здесь не выполнялись.

## Источники

- Anthropic Skills: открытые примеры навыков; документные docx/pdf/pptx/xlsx с отдельными ограничениями не включены.
- Anthropic Knowledge Work Plugins: выбранные рабочие плагины для данных, разработки, поиска и организации работы. Это Cowork, отдельный продукт Anthropic; он не является ChatGPT Work.
- Anthropic Claude Plugins Official: выбранные плагины с процедурами разработки, ревью, MCP и организации проекта.
- OpenAI Plugins: выбранные материалы с найденными MIT/Apache-2.0 лицензиями. Некоторые курируемые плагины созданы сторонними авторами, а не OpenAI. Публичность остальных плагинов не означает разрешения на перенос.
- Orchestra Research AI Research Skills: библиотека ML-инженерии, оценивания и исследовательских процедур.
- K-Dense Scientific Agent Skills: выбранные общенаучные процедуры, статистика и представление результатов.
- Caveman. Навыки кратких ответов, диагностики и завершения проверок. Подключаются профилями `token-style` и `focused-checks`.
- OpenAI Codex: пять публичных файлов с базовыми инструкциями, сжатием истории и рубрикой ревью. Это исходники Codex CLI, не полный системный промпт ChatGPT Work или Claude Code.

Точные URL, commit SHA и указанные в исходниках лицензии находятся в sources.lock.json и catalog.json. Отбор по лицензиям консервативный: материалы без установленной MIT/Apache-2.0 лицензии и явно ограниченные материалы в корпус не добавлялись. Включённые уведомления и лицензии нужно сохранять. Наличие MIT/Apache у процедуры не лицензирует сторонние сервисы, модели и данные, которые она упоминает.

## Подключение к Goose

В Goose Research Kit правила подключения уже находятся в проектной `.goosehints`. При переносе библиотеки в другой проект помести в него папку `portable-research-library/` и добавь содержимое `GOOSEHINTS.append.md` к правилам этого проекта.

По умолчанию библиотека не добавляет сотни skills в контекст и не подключает внешние сервисы. Агент может искать процедуры локальной командой, читать 1–3 подходящих файла и использовать их как рабочее руководство.

```bash
python3 portable-research-library/catalog.py profiles
python3 portable-research-library/catalog.py search "literature review" --limit 5
python3 portable-research-library/catalog.py search "hypothesis experiment" --limit 5
python3 portable-research-library/catalog.py search "evaluation transformers" --limit 5
python3 portable-research-library/catalog.py verify
```

Поиск лексический по метаданным, преимущественно на английском. Он не обращается к моделям или внешним API. Для чтения конкретного файла используй путь из результата либо `catalog.py show ID --text`.

## Нативное подключение небольшого профиля

Можно добавить выбранный набор в `.agents/skills` проекта. Сначала посмотри список действий:

```bash
python3 portable-research-library/catalog.py activate \
  --profile research-core --project .
```

Затем выполни установку:

```bash
python3 portable-research-library/catalog.py activate \
  --profile research-core --project . --apply
```

На Linux создаются символические ссылки на исходные каталоги. Сохраняй библиотеку на месте после подключения. Для Windows можно добавить `--copy`; в скопированный каталог добавятся сведения об источнике и копия лицензии. Существующие навыки не перезаписываются. При конфликте имён проверка останавливает установку до изменений. Повторный запуск ссылочного режима пропускает уже установленные ссылки.

Это импорт исходного skill, не автоматическая адаптация всех его инструментов. Флаги совместимости видны в catalog.json. Фронтматтер с Claude-specific полями, пути, ресурсы соседних skills и внешние сервисы требуют проверки в Goose. Если процедура требует отдельного API/пакета, сам импорт его не устанавливает. После импорта начни новую сессию и проверь `goose skills list`.

## Интеграции

`integrations.json` перечисляет MCP-конфигурации и служебные манифесты выбранных плагинов с путями к исходникам. Это материал для настройки адаптера. Такие записи не свидетельствуют, что сервис уже подключён, пользователь авторизован или что конкретный сервер совместим с Goose.

Для обычных MCP-серверов перенеси поддерживаемый stdio/HTTP транспорт в настройки Goose и настрой авторизацию по документации самого сервиса. Ссылки на внутренние коннекторы Work/Cowork и их идентификаторы нельзя превратить в подключение копированием JSON.

## Публичные промпты

В upstream/openai-codex сохранены публичные примеры базовых инструкций, сжатия и ревью с исходной лицензией. Имена некоторых файлов указывают на конкретные модели: это не рекомендация выбирать эти модели сегодня. Промпты зависят от схем инструментов, системы разрешений и рантайма Codex. Используй их для анализа и точечных адаптаций.

GOOSEHINTS.append.md — самостоятельно написанная общая политика под исследовательские задачи пользователя. Она не воспроизводит закрытые системные инструкции Work или Claude Code. Она задаёт порядок работы с доказательствами, состоянием, экспериментами, прогрессом и остановкой; жёсткие лимиты требуют поддержки рантайма и API-контроля.

## Проверка гипотезы о нехватке процедур

На одной API-модели, с одинаковыми инструментами и бюджетом сравни:

1. Starter без библиотеки.
2. Starter с общей политикой из GOOSEHINTS.append.md.
3. Та же политика плюс 1–3 выбранные процедуры.

Используй реальные задачи и фиксируй сохранность ограничений после сжатия, точность ссылок, завершённость, вмешательства пользователя, стоимость, время и повторные действия. Дополнительные коннекторы проверяй отдельным изменением, чтобы было понятно, откуда пришло улучшение.

В библиотеке нет полного воспроизведения обоих продуктов. Сильная процедура может улучшить работу; исходное качество модели и корректность рантайма продолжают влиять на результат.
