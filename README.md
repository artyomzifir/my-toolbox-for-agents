# Goose Research Kit

Установка Goose для одного пользователя Ubuntu. CLI, Desktop и сессии в разных проектах используют общую конфигурацию Goose.

```bash
git clone ./goose-research-kit.bundle goose-research-kit
cd goose-research-kit
./install.sh
```

Чтобы той же командой установить и **Goose Desktop**, запусти `./install.sh --desktop`. Установщик берёт официальный DEB и устанавливает его через `sudo apt-get`. Основной сценарий рассчитан на Ubuntu 22.04+ с Python 3.10+, x86_64 или ARM64. На Windows используй CLI через Ubuntu в WSL2.

Установка требует доступа к источникам зависимостей. Запускай скрипт от обычного пользователя. Если Goose или uv уже есть, установщик использует их. Для Firefox могут понадобиться системные библиотеки, и Playwright тогда запросит `sudo`.

Чтобы затем клонировать по сети, создай пустой репозиторий у своего Git-хостинга. В клоне выполни `git remote set-url origin URL_РЕПОЗИТОРИЯ` и `git push -u origin main`.

## Первый запуск

Открой новый терминал Bash и запусти `goose` из любой рабочей папки. Если Goose ещё не настроен, выбери свой провайдер и модель в `goose configure` или при первом запуске Desktop. Установщик сохраняет имеющийся выбор и ключи, а также активные настройки сторонних расширений. Для Desktop после установки начни новую сессию.

- Goose CLI устанавливается в `~/.local/bin`, если он ещё недоступен.
- Developer, Skills, Todo, Chat Recall и Playwright включаются в пользовательской конфигурации. Поиск использует встроенный `web-search` в актуальном Goose. Firefox MCP использует абсолютные пути, доступные из Desktop.
- Библиотека и правила копируются в `~/.local/share/goose-research-kit`. Навыки из базовых профилей доступны через `goose skills list`. Клон можно удалить после установки.
- Docling и Python-инструменты документов ставятся через `uv` автоматически при первом обращении. RTK OSS устанавливается при наличии доступа к релизам. Caveman доступен по явной просьбе.
- Повторный запуск обновляет управляемые правила и навыки. При изменении `config.yaml` создаётся резервная копия. Если задан абсолютный `GOOSE_PATH_ROOT`, используется его `config/`.

## Режим разработки

Короткие глобальные правила работают в каждой сессии. Для изменений API, схем, миграций, авторизации и конкурентности, а также для ревью, Goose получает более подробную процедуру `production-engineering`. Её можно вызвать явно через `/skills production-engineering` в CLI.

Процедура требует проследить обычный путь выполнения, определить контракт, проверить затронутые сценарии отказа и запустить штатные проверки проекта. ООП применяется там, где класс выражает состояние и инварианты, а интерфейс нужен для реальной границы подстановки. [Правила](production-rules.md) · [Процедура](skills/production-engineering/SKILL.md)

[Piebald](https://github.com/Piebald-AI/claude-code-system-prompts) использован как справочник по разделению планирования, реализации и ревью. Здесь эти процедуры описаны своими словами с учётом инструментов Goose. Полный корпус привязан к именам инструментов, событиям и сборке контекста в Claude Code.

Каталог, версии и лицензии исходных материалов находятся в [библиотеке процедур](portable-research-library/README.ru.md). [Ручная настройка из исходного архива](README.ru.md) оставлена для справки. Шаблоны [PROJECT_STATE.md](PROJECT_STATE.md) и [SOURCES.md](SOURCES.md) можно скопировать в отдельный исследовательский проект.
