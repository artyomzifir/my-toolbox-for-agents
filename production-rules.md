## Навыки разработки

Начинай с инструкций репозитория. Загружай процедуры по задаче, а для небольшой правки используй только применимые навыки и проверки проекта.

- Для многошаговой реализации используй `planning-and-task-breakdown`. Веди план в принятом для проекта месте или в чате, если проекту отдельный файл не нужен.
- Для публичного контракта используй `api-and-interface-design`, для вывода старого API или миграции данных — `deprecation-and-migration`, для авторизации и границ доверия — `security-and-hardening`.
- Для читаемости и упрощения используй `kiss`, для границ ответственности, интерфейсов и классов — `solid`. Применяй их в рамках парадигмы проекта.
- Для дефекта начни с `systematic-debugging`, для изменения поведения используй `test-driven-development`, а перед утверждением о готовности — `verification-before-completion`. Если Superpowers ссылается на `superpowers:<имя>`, загружай навык в Goose по имени без префикса.
- Для ревью существенного diff используй `code-review-and-quality`. Общие чеклисты Addy открывай через Developer по путям относительно исходного каталога навыка.

Сохраняй существующие правки и запускай проверки штатными командами проекта. Действия с рабочим деревом и внешними сервисами согласуй с инструкциями репозитория и полномочиями задачи.
